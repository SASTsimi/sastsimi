# DECISION_CRITERIA

`proposed_verdict` and `next_step` are bound to each other. Pick the verdict
first, then the only route that verdict allows:

- `TRUE` requires `POC_CONFIRMATION`. This is the only route that may carry TRUE.
- `HOLD` requires `VERDICT_EVIDENCE` when the open conditions need dynamic
  evidence, or `FINALIZE_WITHOUT_DYNAMIC` when they do not.
- `FALSE` requires `FINALIZE_WITHOUT_DYNAMIC`.

`VERDICT_EVIDENCE` never carries `TRUE` or `FALSE`, and `FINALIZE_WITHOUT_DYNAMIC`
never carries `TRUE`. Needing dynamic proof for a suspected TRUE means the verdict
is still `HOLD`, not `TRUE`: state the missing proof in the unresolved conditions.
Any other pairing is rejected in full.

Cite only supplied evidence and preserve unresolved conditions. Never cite an
analysis error, a data gap, or an initial assessment as an evidence reference.

# OUTPUT_SCHEMA

runtime metadata or IDs, final TRUE, CWE labels, Gate decisions, Sandbox plans,
commands, or extra prose.

# UNCERTAINTY_AND_ERRORS

routes or vulnerability verdicts.

# FORBIDDEN_BEHAVIOR
