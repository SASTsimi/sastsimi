# 그룹 보고서 읽기 전용 재생 — 2026-10-04

이 검사는 새 취약점 분석을 시작하거나 기존 DB·체크포인트를 수정하지 않았다.
현재 대시보드의 `outputs` 투영과 동일한 읽기 전용 경로로 저장된 두 로컬
`file://` 시험 대상을 조회했다. 두 저장소는 실제 제보나 일반화된 탐지율의
증거가 아니다.

| 로컬 시험 대상 | 저장된 개별 보고서 | 현행 검증 그룹 | 내보내기 가능한 그룹 ZIP |
| --- | ---: | ---: | ---: |
| `blind-e2e-20261003/targets/antony_flask_oracleless` | 11 | 0 | 0 |
| `blind-e2e-20261003/targets/python_vulns_gnu` | 12 | 0 | 0 |

두 분석 모두 보고서 단계 체크포인트는 각각 11·12건이지만, 모든 해당 Finding의
`VERIFICATION_FINAL_DONE` 저장 단계 버전이 현재 그룹 검증에 필요한 단계
버전과 다르다(각각 11/11·12/12). 따라서 현행 그룹 투영의 검증 가능한
closure는 0건이다. 기존 개별 보고서 링크를 그대로 유지하며 그룹 ZIP을 억지로
생성하지 않는다. **이 저장 자료에서 실측된 중복 보고서 감소는 0건**이다.
저장된 개별 보고서 수를 곧바로 제출 가능한 취약점 수로 해석해서는 안 된다.
새 형식의 검증된 그룹
closure를 가진 합성 회귀 fixture에서는 그룹 ZIP 생성·원본 멤버 보존·오래된
근거 차단을 별도로 시험한다.

확인 명령은 저장 데이터의 `DashboardQuery(data_dir).get_analysis_tab(
analysis_id, "outputs")`를 읽고 `reports`, `finding_groups`, `bundle_url` 수만
집계했다. 원본 DB 바이트를 갱신하거나 새 Finding ID를 할당하지 않았다.
