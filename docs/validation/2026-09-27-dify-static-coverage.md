## 범위와 관찰

고정 checkout에는 Git 추적 파일 13,999개가 있으며, 현재 로컬 규칙 18개가 적용되는 Python·JavaScript·TypeScript 파일은 11,168개다. 적용 가능한 파일·규칙 조합은 97,328개다. 이는 저장소 전체 파일을 모든 규칙으로 검사한다는 뜻이 아니라, 각 규칙 언어와 파일 확장자를 대조한 수치다.

OpenGrep의 여섯 규칙 묶음 중 첫 묶음은 기존 A-007의 같은 checkout·규칙 키에서 얻은 원문을 검증해 별도 시험 ID에 사용했다. 이 첫 묶음은 부분 결과이며 21,210개 파일·규칙 조합의 검사 완료를 확인했다. 나머지 다섯 묶음은 이번 시험에서 공유 실행시간 제한으로 끝내지 못했다. 재시도 실패 후 기존 부분 결과가 DB에서 사라지는 결함을 시험 중 찾아 수정하고 다시 실행했다. 수정된 실행은 이미 검증한 OpenGrep 결과를 보존하면서 AST·CodeQL을 독립적으로 수집하고, 미검증 조합만 Semgrep으로 전달했다. CodeQL은 현재 설정대로 Python 범위만 검사하며 OpenGrep 규칙을 대신 완료한 것으로 계산하지 않는다.

기존 A-007은 PR 코드로 조회하면 `STATIC_DONE · BLOCKED · OPENGREP_PARTIAL_SCAN`이다. 이전 checkout에 editable 설치된 실행 파일은 새 번들 체크포인트 필드를 읽지 못해 `ValidationError`를 냈다. 정적 시험 실행에는 PR 코드만 사용했고, 기존 A-007을 재개하거나 삭제하지 않았다.

실제 Semgrep 원문에는 파일 경로가 특정된 구문 분석 오류가 있다. 해당 파일은 `paths.scanned`에 있더라도 검증 완료로 계산하지 않고, 같은 묶음에서 오류 없이 검사된 다른 파일만 개별적으로 인정한다. 하나의 생성된 JavaScript 파일을 따로 재검사해도 Semgrep이 `Syntax error`를 반환했으므로, 이 조합은 성공으로 승격하지 않는다.

이 저장소의 OpenGrep 미검증 76,118조합을 현재 최대 32파일 단위로 전부 재검사하려면 약 954회 Semgrep 호출이 필요하다. 선택형 fallback에는 전체 1시간 제한이 있어 큰 저장소의 모든 조합이 한 번에 끝난다고 보장할 수 없다. 호출 크기만 무작정 늘리면 실제 출력이 묶음당 수 MB에 이르는 경우 프로세스 출력 한도를 넘을 수 있다. 이 성능 한계는 검사 누락을 숨기는 이유가 아니며, 남은 파일·규칙 조합은 최종 coverage artifact에 기록하고 정적 단계를 `BLOCKED`로 둔다.
