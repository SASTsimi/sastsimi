# Versioned Surface Evidence Enrichment Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Re-evaluate only the unresolved surfaces of a saved Python-only analysis using pinned v4 evidence, preserving all prior records and allowing `COMPLETE` only with a verified v2 coverage certificate.

**Architecture:** Add a deterministic Python-scope recertifier and a bounded, redacted source/AST graph builder beside the v1–v3 path. An explicit same-ID resume option pins an immutable manifest, executes missing v4 parts through the existing surface Agent and child pipeline, then publishes an additive v2 coverage proof. Old readers and runs keep their v1 semantics.

**Tech Stack:** Python 3, Pydantic contracts, SQLite checkpoint store, content-addressed JSON artifacts, pytest/pytest-asyncio, Ruff, Windows PowerShell.

**Spec:** `docs/plans/2026-10-11-a001-versioned-surface-evidence-design.md`

## Global Constraints

- Same analysis ID; leave old SQLite rows, static/index artifacts and hashes, v1–v3 contexts/results, candidates, child work, Findings, PoCs and scope gates unchanged.
- Explicit opt-in `resume --enrich-saved-surface-evidence` under the normal exclusive lease; no implicit replan, static rescan, network install, or bulk DB migration.
- Only the still-`INSUFFICIENT` surfaces (33 of 56 in A-001) are v4 targets; Python static checks are 85/85 in that saved run, but every raw gap/exclusion remains audited.
- A known non-Python extension with reason `non_python_product_source` or `declared_non_python_entry` can be recertified only when tracked and source-hash-bound to the pinned commit; `.py`/`.pyi`, unknown reasons, missing sources and all other gaps stay in scope.
- Retain the 2 MiB single-file read limit. Each prompt-visible JSON part is at most 64 KiB including metadata; atomic lines/facts/edges are never byte-truncated. Bound graph traversal and preserve explicit unavailable/budget reasons.
- Keep the existing surface Agent role, JSON-schema/retry/timeout path, `(analysis, scope, surface, context)` checkpoint key, deterministic child IDs and atomic result-plus-child registration; v4 is additive.
- A surface is covered only with source-verified `ENTRY`, `SENSITIVE_OPERATION`, `TRUST_BOUNDARY` evidence on one verified path and no unresolved child from any version. A model claim is not proof.
- `COMPLETE`/100% requires zero effective Python gaps, every surface covered, no unfinished candidate/child work and intact certificate refs. Evidence insufficiency stays `PARTIAL`; integrity/Agent failure keeps failure semantics. Surface review never upgrades Finding, PoC or Scope Gate.
- Execute on Windows PowerShell with the repository root `.venv`; preserve the concurrent A-002 edits in this worktree. Do not touch the live A-001 DB until implementation and tests are separately approved.

## Review Focus

1. A non-Python path exists in static coverage but its pinned Git blob is absent or the checkout bytes changed: leave an effective gap or fail closed, never recertify it (Task 1 tests).
2. Two same-named handlers or dynamic dispatch create a tempting but unverified cross-file route/call edge: record a graph gap, never synthesize a path (Task 2 tests).
3. A redacted secret or one atomic source line/AST fact exceeds 64 KiB: record unavailable evidence with no raw secret and no partial byte slice (Tasks 2–3 tests).
4. A v4 part is already complete but its CAS result/child ref is missing or a prior child is `HOLD`: do not call the Agent twice or mark the surface covered (Tasks 5–6 tests).
5. A pre-v4 run is opened by CLI/dashboard/report after the new reader ships: keep its former status and v1 proof interpretation (Tasks 6–7 tests).
