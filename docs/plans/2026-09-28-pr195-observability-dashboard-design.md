# PR #195 분석 관측성과 대시보드 설계

작성일: 2026-09-28
대상: `feat/dashboard-recommended` (PR #195)
상태: 구현 전 검토용

## 목표와 범위

PR #195의 대시보드를 최신 `main`의 보안·보고서 기능과 맞추고, 분석 중 사용자가 실제 진행 상황과 중간 산출물을 이해할 수 있게 한다. 기존 분석·판정·Scope Gate 로직을 바꾸거나 후보를 확정 취약점으로 승격하지 않는다. 시연 영상 파일은 Git에 넣지 않고, 재현 가능한 데모 데이터·녹화 절차·시나리오를 제공한다.

## 사용자 경험

첨부한 참조 화면처럼 짙은 중립색 배경, 간결한 간격, 고대비 색상으로 다음 순서를 유지한다.

1. 상단 카드: 정적 탐색 진행률, 가설 검증 진행률, 남은 작업 수, 검증된 Finding 수. 값의 분모와 상태를 함께 표시한다. 아직 집계하지 못한 값은 `—`로 표기하고 0으로 위장하지 않는다.
2. 상태 격자: 참조 화면의 Seed는 SASTSIMI의 가설·작업 단위로 치환한다. 각 칸은 ID·상태를 텍스트와 색으로 같이 나타내고, 클릭 시 근거와 산출물로 이동한다. 항목이 많으면 가상화 또는 페이지 이동을 사용한다.
3. 단계별 진행 막대: AST, OpenGrep, 대체 엔진, CodeQL, 가설 생성, 검증, 보고서 등 실제 실행 중인 단계와 완료/전체 수를 보인다. 분모가 아직 확정되지 않았거나 건너뛴 단계는 구분한다.
4. 실행 이력: 시간, 단계/Agent, 수행 이유, 실제 생성·발견 개수, 성공·실패·재시도를 최근순으로 표시한다. 중간 후보는 `후보`임을 명시하고 확정 Finding과 구별한다.
5. 기존 PR #195의 trace, report, 비교, replay, presentation 기능을 유지하되 최신 `main`의 아티팩트 접근 통제와 보고서 번들 검증을 우회하지 않는다.

대시보드는 한국어 UI를 기본으로 하되 기존 영문 보고서 내용과 다운로드는 원문 그대로 제공한다. 색만으로 의미를 전달하지 않고 키보드 탐색, 반응형 좁은 화면, 스크린리더용 상태 라벨을 지원한다.

## 데이터와 콘솔 로그

기존 SQLite 체크포인트·정적 검사 실행 기록·`AgentActivityEvent`를 진실 원천으로 사용한다. 새 이벤트가 필요한 경우 기존 모델에 선택적 `substage`, `metrics`(검증된 비음수 정수), `artifact_refs`를 더하는 작은 확장으로 제한한다. 별도 카운터를 임의로 재계산하거나 화면용 가짜 실행 이벤트를 운영 DB에 기록하지 않는다. 기존 DB와 이벤트는 마이그레이션 없이 읽혀야 한다.

스캐너 경계와 Agent 완료 시점에 시작/성공/실패/재시도 이벤트를 남긴다. AST·OpenGrep·Semgrep 대체 검사·CodeQL 각각에 대해 파일/규칙 범위, 처리·미처리 수, 발견 건수를 확인 가능한 원천에서만 기록한다. 후보 생성과 Finding 확정도 서로 다른 종류로 기록한다. 취소와 재개 시 동일 작업을 완료로 중복 집계하지 않는다. 콘솔 렌더러와 대시보드가 같은 저장 이벤트/체크포인트를 읽어 단계명과 수치가 일치하도록 한다.

일반 로그에는 키, 전체 프롬프트, 원시 PoC/저장소 코드, 내부 호스트 경로, 숨겨진 추론을 쓰지 않는다. 후보 요약은 ID·분류·파일 위치 등 이미 공개 가능한 검증된 메타데이터로 제한하고 길이를 제한한다. 상세 근거는 권한이 확인된 아티팩트 뷰에서만 연다.

## Reasoning level 설정

공통 기본값과 Agent별 override를 선택적으로 추가한다. 지정하지 않으면 현재 provider 동작을 보존한다. CLI 인자, 환경변수, 설정 파일의 우선순위는 기존 모델 설정 규칙에 맞추고 적용된 수준을 로그에는 값만 표시한다. 지원 가능한 값은 provider/모델 기능으로 검증한다.

- Codex CLI: 공식 `model_reasoning_effort` 설정을 사용한다.
- OpenAI Responses 경로: 공식 `reasoning.effort` 지원 모델에서만 전달한다.
- Claude CLI: 공식 `CLAUDE_CODE_EFFORT_LEVEL` 지원 범위에서만 전달한다.
- Cursor: 설치된 SDK의 모델 카탈로그/파라미터가 effort에 해당하는 값을 명시할 때만 사용한다. Cursor CLI 경로 또는 해당 모델에서 확인되지 않으면 조용히 무시하지 않고 명확히 거절한다.

모델 ID나 level을 추측·하드코딩하여 지원된다고 선언하지 않는다. Agent override > 공통 기본값 순서이며, 미지원 provider/모델 조합은 분석 시작 전 오류로 알린다. 재개 시 저장된 실행 설정과 새 설정의 충돌을 감지한다.

## 아티팩트 뷰어

확인된 분석 ID 및 아티팩트 참조만 서버 API에 전달한다. 임의 로컬 경로·URL을 열지 않는다. `.md`는 보고서와 일반 아티팩트 모두 같은 CommonMark 렌더러로 표시하고 HTML을 정제해 스크립트·위험한 URL·임의 HTML 실행을 막는다. 코드 블록, 표, 링크, 목록을 지원하며 원문 다운로드를 둔다. JSON은 접고 펼칠 수 있는 포맷 뷰, 평문은 개행 보존, 바이너리는 미리보기 없이 내려받기로 구분한다. 대용량은 크기 제한·부분 보기·다운로드를 명확히 표시한다. #194/#202의 서버 측 경로·번들 검증을 유지한다.

## 시연 준비

민감 정보가 없는 고정 샘플 데이터를 테스트 fixture로 제공해 카드·상태 격자·이력·마크다운 뷰를 재현 가능하게 한다. 실제 분석과 데모 모드를 혼동하지 않도록 `DEMO` 배지를 붙이고 제출 가능 보고서로 연결하지 않는다. Windows PowerShell용 녹화 도우미는 화면 녹화 도구의 설치 여부를 검사하고, 로컬 대시보드를 열어 사용자 지정 저장 경로로 녹화를 시작·중단하게 한다. 녹화 범위와 민감 정보 노출 위험을 시작 전에 명시하며, 녹화 도구가 없을 때는 설치 방법과 수동 녹화 경로를 안내한다. 시작/녹화/종료 절차와 3~5분 발표 시나리오를 문서화한다. 실제 MP4 촬영·전달은 저장소 밖 별도 산출물이며, 이번 PR의 성공 조건은 재현 가능한 화면·녹화 도우미·시나리오다.

## 통합 및 검증

PR #195를 최신 `origin/main`과 통합할 때 #194의 접근 통제와 #202의 이중 언어 보고서 번들을 보존한다. 충돌은 파일별로 검토하고 원격 변경을 덮어쓰지 않는다. 작업 전후에 PR 브랜치와 최신 main 차이를 확인한다.

필수 테스트: 설정 우선순위·미지원 effort 거절, provider별 전달/미전달, 스캐너 단계 이벤트와 재개 시 중복 방지, 실제 수치/미집계 구분, 후보/확정 분리, 로그 민감 정보 차단, 512개 초과 항목 집계, 대시보드 응답·접근 통제, Markdown XSS·위험 링크·대용량 처리, 모바일 레이아웃과 키보드 동작, 데모 fixture. 기존 전체 테스트·정적 검사·문서 링크 검사와 최소 실제 화면 확인 후 PR에 결과를 적는다.

## 완료 기준과 제외 사항

콘솔과 웹에서 같은 실행 단계를 추적할 수 있고, 모든 `.md`가 안전하게 렌더링되며, 참조 화면의 정보 구조가 실제 SASTSIMI 데이터에 맞게 동작해야 한다. 미확정 후보는 미확정으로, 실행 오류는 오류로 남긴다. 이 작업은 취약점 판정 기준, PoC 실행 정책, Scope Gate, 실제 시연 영상의 제작·업로드를 변경하지 않는다.
