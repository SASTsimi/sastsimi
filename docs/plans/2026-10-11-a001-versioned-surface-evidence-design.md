# Versioned surface evidence enrichment for an existing partial analysis

## Intent and acceptance boundary

An existing Python-only analysis (A-001) finished its 85/85 static file-rule checks, yet remains `PARTIAL`: its saved scope/index contains three non-Python product-file exclusions, and 33 of 56 attack surfaces are `INSUFFICIENT` after v1–v3 review. The aim is to retry **only those unresolved surfaces** using better, source-bound context and to recertify the exact Python scope without losing any prior work. This is not a promise that the analysis will reach 100%: missing code, unresolved child `HOLD`, failed agents, or genuine Python static gaps must remain visible and prevent `COMPLETE`.

Success means the same analysis ID can resume from an immutable v4 plan; old SQLite records, CAS artifacts, candidates, child results, v1–v3 context/results, and the original static/index hashes remain readable and unchanged. A new coverage certificate may count a surface as `COVERED` only when its entry, sensitive operation, and trust boundary have distinct, precise, source-verified evidence and no related child is unresolved. The existing Finding/PoC/scope-gate decisions are not upgraded by a surface review.

## Approaches considered

1. **Chosen: additive, exact-scope certificate and targeted v4 review.** Pin the existing evidence, append a Python-scope recertification and a v4 context plan, then checkpoint only new context decisions. Final status derives from the certificate and verified surface/child state. This preserves old hashes and makes a failed or interrupted repair auditable, at the cost of one additive reader/terminal format.
2. Rebuild the static bundle and attack-surface index under the current code. This simplifies the current code path but changes content hashes and surface IDs, invalidating old progress or forcing a fragile migration of every linked candidate and child. Reject for same-ID repair.
3. Special-case `PARTIAL`/96% into `COMPLETE` when the three paths end in `.js`. This is cheap but does nothing for the 33 insufficient surfaces, bypasses evidence, and misstates completion. Reject.

## Immutable plan and scope recertification

The repair entry point is explicit for saved runs (for example, a narrowly named `resume --enrich-saved-surface-evidence` option). It takes the normal exclusive analysis lease. Before any LLM call it validates the pinned workspace/commit, static bundle, coverage artifact, AST manifest and per-file source SHA-256 values, candidate inventory, surface index, prior coverage and all v1–v3 progress refs. It computes a deterministic `simple_surface_enrichment_plan_v4` artifact from the analysis ID, workspace/commit, existing scope fingerprint, static/index/AST/candidate hashes, exact target surface IDs, their prior effective context IDs and result hashes, code-reader/prompt revision, and the source hashes of selected files. An optional new ref on `SimpleAnalysisRun` pins the plan once; a second resume recomputes and byte-compares it. A different result fails closed as a scope change, never silently replans.

The same plan contains a separate `simple_python_scope_recertification_v1` certificate. It lists **every** raw static gap and exclusion, the exact path/extension/reason, the original static coverage ref and index hash, and the in-scope decision. Only a tracked, source-hash-bound, known non-Python extension with the proven reasons `non_python_product_source` or `declared_non_python_entry` may be reclassified as out of the Python-only static scope. The three legacy JS entries are eligible only if each passes this test against the pinned commit; there is no path-specific exception. Unknown reasons, `.py`/`.pyi`, a missing file, an unverified file-rule pair, a parser/engine error, or any other static gap stays in scope. The certificate preserves raw gaps and excluded paths in the audit record. It does not overwrite `run.static_disposition`, `STATIC_DONE`, the old coverage artifact, or the old surface index.

Final coverage uses a versioned additive artifact, such as `simple_attack_surface_coverage_v2`, with original raw gaps, effective in-scope gaps, scope-certificate ref, per-surface evidence refs, and the unchanged index hash. `complete` requires zero effective Python gaps, every indexed surface covered, no unfinished candidate/child work, and verified certificate hashes. The candidate terminal and CLI/dashboard projections must use this **effective** proof only for the explicit repair; old terminal/artifact readers retain their original meaning. Merely appending a certificate must not flip a terminal or progress percentage.

## Targeted v4 context construction

Select the 33 surfaces still `INSUFFICIENT` under the saved v1–v3 evidence, not all repository files or already-covered surfaces. For each selected surface, reconstruct and persist a source-bound evidence graph from:

- the entire enclosing Python function/class or module-level parent span containing the surface (not just nearby lines), including decorators and the relevant route registration;
- AST facts omitted or isolated by earlier v2 parts, paired with their actual source lines;
- local route-to-handler and direct callee definitions needed to explain entry and trust boundary, including related Python files only when the call/route link is verified against the pinned AST/source.

The graph records typed edges and `path:line` spans for entry, call, operation, and boundary; an unresolved dynamic dispatch or unavailable external implementation is an explicit gap, not an inferred edge. Traversal is deterministic, cycle-safe and bounded by a documented maximum node/edge budget per surface. Exceeding that budget yields `CONTEXT_BUDGET_EXHAUSTED` and leaves the surface insufficient. The existing 2 MiB single-file reader limit, oversized/unsafe source, failed redaction, source-hash mismatch, or missing AST facts similarly produce explicit unavailable reasons rather than a fabricated review. No new network dependency installation is part of this repair.

Redact before storing prompt-visible code. Split every selected source span and AST/edge list into deterministic JSON parts of at most 64 KiB **including metadata**; do not cut bytes from a line, fact, or edge. An oversized atomic item is reported unavailable. Each v4 context has a content hash, deterministic context ID, part index/count, source/AST hashes, original index and scope hashes, parent v2/v3 IDs where applicable, and plan hash. Save a manifest of all expected parts first. A prompt receives only one bounded part plus a compact manifest and immutable location refs, not the full source repeated for every part. Unknown or missing parts remain `PENDING`/insufficient.

## Review, child work and terminal semantics

The existing surface Agent role and strict JSON-schema/retry/timeout path remain. It returns a versioned result for one v4 part: `HYPOTHESES`, `NO_HYPOTHESIS`, or `INSUFFICIENT_EVIDENCE_FOR_HYPOTHESIS`, a reason, optional hypothesis seeds, and per-role evidence objects (`ENTRY`, `SENSITIVE_OPERATION`, `TRUST_BOUNDARY`) with `path:line`, cited context/source ref, and explanation. Each role claim must resolve to an actual line in the pinned redacted source and, where it claims a cross-file route/call, to a verified graph edge. A model assertion alone, or a union of unrelated roles across parts, is not proof of one path. The existing surface location must be cited. Invalid JSON/schema, invented location, source mismatch, missing part, or failed child remains error/pending evidence; it cannot become a successful `NO_HYPOTHESIS`.

Use the existing `(analysis, scope, surface, context)` progress key with `proposal_version=4` and an atomic result-plus-child registration; keep all version 1–3 rows untouched. Deterministic seed IDs and compare-and-set prevent duplicate child work. On resume, validate the plan, context, result, registration, and child output refs before reusing a completed part; run only missing v4 parts and unfinished children. Reopen only the final surface-coverage/terminal checkpoint for a verified plan; do not replay static checks, Discovery, completed candidate/Agent work, or chaining batches. A crash between result persistence and terminal publication must be idempotent.

A v4 review can repair an insufficient earlier context only when all required roles are proven for the **same** surface and relevant prior omissions are accounted for. It cannot override an unresolved `HOLD`, blocked, pending or failed child from any version. Those children require their own valid recovery or leave the surface insufficient. A genuinely inconclusive hypothesis is not a false positive and is not upgraded to confirmed. If all work is terminal but a surface still lacks evidence, preserve `PARTIAL` and its reason. If integrity or Agent execution fails, retain the existing failure/BLOCKED semantics rather than substituting `PARTIAL`.

## Components and compatibility

- A focused v4 plan/context builder alongside `surface_contexts.py` and `surface_supplemental_contexts.py` owns deterministic source/AST graph extraction and bounded chunking; it does not change the v1–v3 builders.
- `bootstrap_stages.py` validates only the new v4 context/result schema and keeps old response schemas unchanged. `store.py` permits proposal version 4 and retains the existing exact-key atomic progress contract.
- `application.py` prepares and pins the plan under lease, schedules only missing v4 contexts, validates replay, and produces the v2 coverage/terminal certificate. The static-scope classifier remains centralized in `contracts/python_coverage_scope.py`; a new recertifier consumes it rather than maintaining a JS-specific list.
- `models.py` receives only optional plan/certificate refs and a versioned terminal proof marker. Readers of old runs, coverage v1, and candidate terminals continue to work without migration or a bulk DB rewrite. UI/report status should show raw exclusions, effective Python coverage and unresolved surface/child reasons separately.

## Verification and rollout

Test first with deterministic fixtures: exact legacy three-JS recertification; a true Python parser/rule gap that still blocks; one covered, one insufficient, and one unresolved-HOLD surface; enclosing parent, orphan AST, cross-file route/callee, cycle, dynamic call, oversized line, secret redaction, source mutation, missing/corrupt CAS, invalid model location, chunk-boundary and >64 KiB no-truncation cases. Assert v1–v3 artifact bytes and existing rows are unchanged, v4 crash/restart reuses completed parts without another Agent call, competing resumes cannot duplicate children, and old analyses without an explicit v4 plan retain their original status. Verify progress/CLI/dashboard/report projections never equate a surface review with a Finding or scope-gate approval.

After unit/integration and regression tests, take a read-only snapshot of A-001, run the explicit same-ID repair once, then compare before/after counts and artifact hashes. Report remaining insufficient surfaces, unresolved HOLDs, effective Python gaps, PoC/Finding status, and model usage. Only a valid terminal certificate with all conditions satisfied may produce `COMPLETE`/100%; otherwise the honest result is `PARTIAL` or an existing failure state. Do not alter the original A-001 DB until the design and implementation plan are separately approved.
