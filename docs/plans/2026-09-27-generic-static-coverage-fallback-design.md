# 범용 정적 검사 커버리지와 선택형 재검사 설계

## 목적과 완료 기준

SASTsimi는 특정 저장소의 오류를 예외 처리하지 않는다. 분석 대상의 고정된 Git 커밋, 추적 파일, 활성화된 규칙을 기준으로 무엇을 검사해야 하는지 계산한다. **설정된 규칙이 적용 가능한 파일을 실제 검사했는지** 증명하고, 증명되지 않은 조합을 조용히 완료 처리하지 않는 것이 목표다. 이는 모든 언어의 모든 취약점 발견이나 모든 저장소의 `COMPLETE`를 보장하지 않는다.

실제 저장소 현장 시험은 속도를 위해 Dify의 고정 커밋 하나만 사용한다. 구현에는 Dify 이름·경로·파일명·오류 문자열을 특별 취급하지 않는다. 작은 합성 저장소를 사용하는 단위·통합 테스트는 범용 동작 검증에 포함한다.

## 검토한 접근

1. Dify에서 오류가 난 파일을 제외하거나 경고를 무시한다: 빠르지만 누락을 숨기므로 채택하지 않는다.
2. OpenGrep을 전면 교체한다: 기존 결과와 재개 기록을 한꺼번에 바꾸므로 이번 범위에는 과하다.
3. **선택안 — 기존 OpenGrep을 유지하고 실패 범위만 재검사하며 커버리지를 증명한다.** 기존 성공 묶음을 재사용하고 변경 범위를 제한한다. 대체 엔진도 실패하면 명시적으로 `BLOCKED`로 남긴다.

## 검사 범위와 기록

- 고정 커밋에서 `git ls-files -z`로 얻은 추적 파일과 규칙 카탈로그의 규칙 ID·언어를 결합해 적용 대상인 `파일 × 규칙` 조합을 정한다. 지원 확장자·언어 매핑은 버전이 있는 범용 정책으로 관리하고, 알 수 없는 소스 언어는 `미지원`으로 별도 표시한다. README·이미지처럼 규칙 대상이 아닌 파일은 검사 누락으로 세지 않는다.
- 검사 결과가 0건이어도 도구가 대상 파일을 검사했고 해당 규칙을 건너뛰지 않았으며 관련 파싱·내부 오류가 없을 때만 그 조합을 `검사 완료`로 기록한다. `paths.scanned`만으로 완료를 인정하지 않는다. 경로가 없는 전역 오류는 해당 실행 묶음 전체를 미검증으로 처리한다.
- 파일·규칙별 상태는 고정 커밋, 추적 파일 목록 해시, 규칙 해시, 도구 버전·실행파일 해시와 함께 저장한다. 모든 조합을 개별 DB 행으로 늘리기보다 묶음 결과와 실패 목록에서 계산 가능한 압축된 커버리지 artifact를 사용하고, DB에는 시도 상태·지문·artifact 참조를 기록한다. 원본 JSON과 요약은 분리하고, 대시보드에는 상대 경로·실패 원인·엔진·검사 수를 보여준다.
- Python AST는 후보 사실 추출, CodeQL은 별도 질의 결과이며 OpenGrep 규칙의 대체 증거로 간주하지 않는다. AST의 파싱 오류·크기 제한·사실 수 제한도 결과에 드러내되, OpenGrep 규칙 커버리지를 허위로 보완하는 데 쓰지 않는다. 현재 CodeQL 질의가 Python 중심이라는 점도 UI와 문서에서 분명히 한다.

## 실행 흐름

1. 저장소를 준비하고 추적 파일 목록을 고정한 뒤 AST, OpenGrep, 설정된 CodeQL을 각각 실행한다. 한 도구가 실패해도 나머지 도구는 실행하고 각 성공·실패 원본과 artifact 참조를 저장한다.
2. OpenGrep의 각 규칙 묶음에서 결과, `errors`, `paths.scanned`, 건너뛴 규칙·파일을 검증한다. 정상 조합은 기존 성공 묶음 캐시를 재사용한다. 파싱·내부 오류나 누락된 파일만 재검사 대상으로 추린다.
3. 선택형 로컬 Semgrep CE adapter가 있으면 **실패한 파일과 관련 규칙만** 동일한 로컬 규칙 카탈로그로 재검사한다. 분석 중 자동 설치, 계정 로그인, 네트워크 규칙 다운로드, 저장소 소스 수정은 하지 않는다. Windows `.venv`에서 설치·설정 방법을 문서화한다.
4. Semgrep 결과도 JSON 형식, 규칙 ID, 상대 경로, 스캔·스킵 목록, 오류, 실행 종료 상태를 검증한다. 파싱 오류가 없고 적용 대상 조합을 실제 처리했을 때만 대체 성공으로 인정한다. 다른 엔진의 결과를 원본 OpenGrep 결과로 위장하지 않고 엔진 출처를 남긴다.
5. OpenGrep 오류가 남아도 AST·CodeQL 결과와 커버리지 artifact를 조회할 수 있다. 모든 **지원 범위**의 적용 조합이 OpenGrep 또는 인정된 대체 실행으로 증명되고, AST·설정된 CodeQL 같은 독립 도구가 정상 종료한 경우에만 정적 단계가 완료된다. 재검사 도구가 없거나 실패했거나 건너뛴 조합이 남으면 정확한 이유와 경로 목록을 보여주고 `BLOCKED`로 끝낸다.

## 재개와 오류 처리

- 재개 시 고정 커밋·파일 목록·규칙·도구 지문이 같은 성공 결과만 재사용한다. 실패 또는 미완료 실행만 다시 시도한다. 지문이 달라지면 해당 결과를 새로 검사한다.
- 모든 하위 프로세스에 시간 제한과 취소를 전달한다. 오류 코드는 `도구 미설정/실행 실패/파싱 실패/커버리지 미완료`를 구분한다. 동일한 입력·도구 지문에서 반복되는 결정적 파싱 오류는 OpenGrep만 다시 실행하지 않고 대체 실행으로 넘기며, 대체 실행도 실패하면 `BLOCKED`로 종료한다.
- 오류 원본은 artifact에 보존하되 일반 로그와 대시보드에는 제한된 길이의 원인·상대 경로만 표시한다. 절대 사용자 경로와 대규모 소스 내용이 일반 로그로 흘러나오지 않도록 한다.
- 정상 결과와 대체 결과의 finding은 규칙 ID·상대 경로·위치를 기준으로 중복을 제거하되, 양쪽 원본과 엔진 출처는 유지한다. 파싱 실패를 취약점 반증이나 `0 finding`으로 바꾸지 않는다.

## 검증과 비범위

- 단위·통합 테스트: 결과 0건이지만 정상 검사, 부분 파싱, 전역 오류, 스킵, 잘못된 JSON, 대체 엔진 성공·실패·미설정, CodeQL 독립 실행, 취소·시간 초과, 재개 중복 방지, 지문 변경, artifact 훼손, 경로 이탈을 다룬다. 실제 Semgrep 인증정보 없이 mock으로 전체 테스트를 실행한다.
- 현장 시험: 고정된 Dify 커밋에서 OpenGrep 경고를 재현하고, 선택형 Semgrep CE가 해당 파일·규칙을 실제 처리하는지 확인한다. 성공하면 이어서 분석을 재개한다. Semgrep도 실패하면 `COMPLETE`를 주장하지 않고 남은 파일·규칙과 원인을 보고한다.
- 다른 실제 저장소를 추가로 돌리는 것은 이번 빠른 현장 시험의 범위 밖이다. 다만 구현과 합성 테스트는 저장소 식별자에 의존하지 않아야 한다. 보안 규칙 자체의 탐지율, 미지원 언어의 분석, 취약점이 전혀 없다는 보장은 이 설계의 비범위다.
