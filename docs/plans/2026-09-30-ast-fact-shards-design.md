# 파일별 AST 사실 보존과 선택적 Agent 문맥 설계

## 목적과 범위

SASTSIMI의 Python 제품 코드 AST 사실은 현재 분석당 10,000건 이후 저장되지 않는다. 파일별로 파싱에 성공한 모든 사실을 보존하고, Agent에는 해당 후보 또는 소스 페이지에 필요한 일부만 유한한 크기로 전달한다. OpenGrep·Semgrep·CodeQL의 후보 수집 및 기존 Agent 역할은 유지한다. 이 변경은 모든 취약점을 발견한다는 보장이 아니며, 파싱할 수 없는 제품 파일을 완료로 위장하지 않는다.

## 선택한 방식

단일 무제한 AST JSON은 프롬프트와 메모리를 키우고, 단순히 상한을 올리면 잘리는 시점만 늦춘다. 대신 기존 콘텐츠 주소 기반 아티팩트를 사용해 파싱된 Python 파일마다 사실 JSON을 저장한다. 별도 manifest는 상대 경로, 사실 건수, 해당 아티팩트 참조를 정렬된 순서로 보유한다. 정적 번들에는 전체 사실이나 manifest 목록을 복제하지 않고 manifest 참조와 총건수·파일 수·오류 요약만 넣는다. `tool_result_refs[0]`의 기존 AST 참조 역할은 소형 요약으로 유지한다.

한 파일에서 추출한 FunctionDef·AsyncFunctionDef·ClassDef·이름이 있는 Call 사실은 기존 필드·순서를 유지한다. 분석 전체 사실 수 상한은 없앤다. 파일 읽기 안전성, 파일당 2 MiB 제한, `.py`/`.pyi` 선택 및 테스트 전용 파일 제외는 유지한다. 파싱 오류·초과 파일은 경로와 사유를 남기고 `PARTIAL` 판정에 반영한다. 사실이 정확히 10,000건인 경우도 누락으로 표시하지 않는다.

## Agent 문맥

Discovery의 후보 원본과 정적 검증 기록은 그대로 둔다. 후보 심층 분석용 가설 Agent에는 후보 경로·줄 주변의 AST 사실을 manifest에서 읽어 작은 결정적 묶음으로 첨부한다. 한 파일의 사실이 많아도 전체는 저장되며, 전달하지 않은 건수와 원본 참조를 명시한다. 자유 탐색 경로는 기존 유한한 소스 페이지를 사용하므로 전체 AST manifest를 프롬프트에 싣지 않는다. 기존 `prompt_context`의 256 KiB 조용한 절단에 AST를 맡기지 않는다. 문맥이 너무 크면 해당 묶음을 줄이거나 명시적으로 실패하며, 성공으로 오인하지 않는다.

## 무결성·재개·호환성

새 manifest는 파일별 참조의 해시·경로·건수와 총합을 검증한다. 참조가 없거나 손상되면 AST 완료 증거로 취급하지 않고 기존 근거 손상 실패 상태를 사용한다. 기존 인라인 `ast_summary.facts`를 가진 분석 기록은 읽을 수 있게 남긴다. 새 형식의 번들 해시는 달라지므로 새 분석의 Agent 체크포인트가 옛 AST 입력을 재사용하지 않는다. 동일 범위의 검증된 OpenGrep·Semgrep·CodeQL 결과만 기존 방식으로 재사용한다. 과거 Dify 분석을 새 형식에 억지로 이어 붙이지 않는다.

## 검증과 실제 실행

로컬 테스트는 LLM·Docker·네트워크를 mock으로 대체하고, 10,000건 초과 저장, 다수 파일, 단일 거대 파일의 제한된 Agent 문맥, 256 KiB 초과 manifest, 누락·손상된 참조, 파싱 오류, 기존 분석 호환 및 재개를 확인한다. 전체 회귀·정적 품질 검사를 통과한 후에만 Dify의 한 고정 커밋으로 새 분석을 한 번 실행한다. 이 실제 분석에만 누적 시간·토큰 한도를 `unlimited`로 적용하고, 개별 호출 timeout·재시도·취소는 유지한다. 사용자 프로필과 기존 DB·아티팩트는 덮어쓰지 않는다. 결과는 정적 검사 범위, AST 사실/파일 수, 후보·가설·Finding 수, 남은 오류와 최종 상태를 그대로 보고하며 `COMPLETE`나 `confirmed`를 강제하지 않는다.
