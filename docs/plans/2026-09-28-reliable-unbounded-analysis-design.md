# 중단 없이 재개 가능한 분석 파이프라인 설계

## 목표와 계약

모든 새 분석의 기본 누적 실행시간 제한을 없앤다. Dify 고정 커밋 8387590ace4a094de812b7847fc6a4c3a27cd52b의 기존 A-007을 이어서 정적 검사부터 Agent, 로컬 Docker PoC, 게이트, 보고서까지 실제 검증한다. 저장소별 예외를 코드에 넣거나 기존 체크포인트와 사용자 변경사항을 덮어쓰지 않는다.

COMPLETE는 모든 선택된 분석 단계가 오류 없이 종결됐다는 뜻이지 취약점 확정이 아니다. confirmed와 제출용 영·한 보고서는 성공한 동적 검증과 기존 최종 TRUE·게이트 계약을 만족하는 Finding에만 허용한다. Dify에 취약점이 있다고 가정하거나 결과를 만들어내지 않는다.

## 선택한 접근

1시간 상한만 없애는 방식은 빠르지만 재실행 낭비와 파싱 오류가 남는다. 테스트·생성·벤더 파일을 자동 제외하면 빠르지만 검사 범위를 바꾸므로 채택하지 않는다. 누적 시간 상한 제거, 파일·규칙별 성공 증거 재사용, 미검증 조합의 단독 재검사를 결합한다. 병렬화는 직렬 경로를 측정한 뒤 필요할 때만 추가한다.

## 시간·비용·취소

설정과 setup의 기본 누적 실행시간은 명시적 unlimited로 하고 기존 양의 정수 설정은 유한 한도로 계속 유효하게 한다. 정적 검사와 LLM 누적 시간 게이트에 함께 적용한다. 개별 OpenGrep·Semgrep·CodeQL·Docker·LLM 호출에는 유한 타임아웃과 재시도 횟수, 메모리·출력 제한을 유지한다. 토큰·비용 한도와 사용자 취소도 유지한다. 무제한은 같은 실패를 영구 반복한다는 뜻이 아니다.

## 정적 증거·재개

고정 커밋, Git 추적 파일, 규칙·도구 지문에서 적용 가능한 파일·규칙 조합을 만든다. OpenGrep은 묶음으로 실행하고 검증되지 않은 조합만 Semgrep CE로 재검사한다. 해당 파일이 paths.scanned에 명시되고 오류·skip이 없으며 해당 규칙 실행이 확인돼야 성공으로 인정한다. AST와 현재 Python 범위 CodeQL로 JavaScript 규칙 완료를 주장하지 않는다.

성공 원문과 참조는 묶음 경계가 바뀌어도 정확한 입력·도구·규칙 지문에서 재검증해 재사용한다. 실패 조합은 이미 성공한 조합을 지우지 않는다. 하위 프로세스는 유한하게 끝내고 실패 묶음을 단일 파일·규칙까지 쪼갠다. 검증할 수 없는 조합은 경로·규칙·원시 오류·시도 횟수를 artifact에 남기고 정적 단계를 BLOCKED로 둔다.

## Dify의 관찰된 장애 처리

별도 정적 시험은 적용 조합 97,328개 중 53,910개를 검증했다. 남은 42,953개는 전역 시간 상한, 462개는 147개 JS/TS 파일의 파싱 오류, 3개는 별도 web/public/pdf.worker.min.mjs의 규칙별 시간 초과였다. 147개 중 테스트 135개, 생성 계약 3개, 공개 벤더 번들 5개, 다른 소스 4개다. 이 분류는 우선순위에만 사용하고 자동 제외하지 않는다.

파싱 실패는 파일·규칙을 단독 실행해 실제 소스 오류와 엔진 문법 지원 부족을 구분한다. 호환 엔진이나 의미가 검증된 대체 규칙이 오류 없이 검사하면 원문과 증거를 저장한다. PartialParsing이나 문자열 검색만으로 같은 규칙을 검사했다고 인정하지 않는다. PDF worker의 30초 재시도는 기록만 있고 완료 원문이 없으므로 전역 제한 제거 후 독립된 유한 자원 한도에서 재시험한다. 실패가 남으면 정확한 조합을 BLOCKED로 보존한다.

## Agent·PoC·보고서

정적 단계가 증명된 뒤 동일 분석 ID·커밋의 A-007을 resume한다. 완료 checkpoint는 동일 입력 참조와 단계 버전일 때만 재사용한다. 호환성 문제가 생기면 재실행 단계를 명시하고 조용히 새 분석으로 바꾸지 않는다. Agent·PoC·게이트 오류를 취약점 반증으로 바꾸지 않는다. 근거 부족은 미확정으로 종결할 수 있지만 실행 오류는 BLOCKED다. 확인된 Finding만 PoC·evidence·영문 제출용·한국어 설명용 보고서를 생성한다. 실제 제보는 자동 수행하지 않는다.

## 검증

- 단위·통합: 무제한 기본/기존 유한 설정, 호출별 타임아웃, 취소, 토큰·비용 한도, 중단·재개, 묶음 변경 후 증거 재사용, 원본 손상, 파싱 실패, 단일 파일 시간 초과, 분석 ID 격리.
- 범용 회귀: Python·JS/TS의 양성·음성 fixture, 생성·테스트·벤더 경로, Windows PowerShell·Linux CI. 양성은 검증된 Finding·보고서, 음성은 Finding 없는 COMPLETE, 엔진 미지원은 허위 성공 없는 BLOCKED를 확인한다.
- 실제 Dify: 정적 조합 전부가 증명되거나 남은 장애를 정확히 기록한다. 정적 단계가 통과한 경우에만 뒤 단계로 진행한다. 취약점이 없으면 제출 보고서도 없다.
- 전체 pytest, Ruff, mypy, 문서 검증 및 외부 도구의 실제 결과를 기록한다. 미실행 검사를 통과했다고 보고하지 않는다.

## 한계

임의의 저장소가 모든 파서·규칙에 호환되고 실제 취약점을 포함한다는 보장은 불가능하다. 범용성은 같은 입력에 같은 증거를 요구하고 실패를 정직하게 보고하며 안전하게 재개하는 성질로 검증한다.
