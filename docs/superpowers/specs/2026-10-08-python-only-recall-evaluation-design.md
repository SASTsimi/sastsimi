# Python 전용 탐지율 평가와 최종 안정화 설계

작성일: 2026-10-08 · 기준: 새 작업 브랜치의 최신 `main` (`f49559ab`)

## 목적과 경계

SASTSIMI를 Git 저장소의 제품용 Python `.py` 코드에 집중시킨다. 대상 커밋에서 사전에 고정·검토한 취약점 사례와 저장된 분석 결과를 비교해, 어디서 놓쳤는지 측정하고 관측된 공통 원인만 수정한다. 엄격한 PoC·Technical Gate·Scope Gate 기준은 유지한다. README는 사용자가 설치, 분석, 결과 해석을 빠르게 이해할 수 있게 정리한다.

성공 조건은 (1) 정답표를 분석 입력에서 분리하고 대상 커밋과 연결, (2) Python 사례별 정탐·미탐·환경 보류·검사 범위 밖·검토 중을 근거로 구분, (3) 같은 정답 사례의 중복 Finding을 한 번만 계산, (4) 실제 확인된 Python 누락 원인에 대한 범용 수정과 전후·보류 저장소 검증, (5) 새 PR의 테스트 및 문서 정합성이다. 모든 저장소에서 미탐 0이나 제보 가능 Finding 생성을 보장하지 않는다.

## 선택한 접근

현재 main의 `recall_audit.py`와 읽기 전용 CLI를 확장한다. 평가용 정답표·판정은 분석 파이프라인의 입력, Agent 프롬프트, 정적 규칙 생성에 넣지 않는다. 정답표의 위치·원인을 분석 도중 알려 주거나 `TRUE` 기준을 완화해 점수를 올리지 않는다. 전체 파이프라인을 새 평가 시스템으로 교체하거나 대시보드에 성급한 탐지율을 표시하는 변경도 하지 않는다.

## 데이터와 판정

사전 정답표는 저장소 URL, 정확한 소문자 commit SHA, 정답표 버전·작성 근거·범위 완전성 선언을 가진다. 각 사례는 안정적 ID, CWE, Python 진입점과 위험 동작의 개별 파일·위치, 재현 전제, 출처, Python 범위 해당 여부와 근거를 가진다. 기존 단일 파일 oracle 형식은 계속 읽되, 새 형식에서 서로 다른 source/sink 파일을 허용한다. 정답표는 분석 시작 전에 해시와 검토 기록으로 고정하고 대상 checkout 밖에 둔다. 커밋이나 내용이 다르면 평가를 거부한다. 기존 로컬 시험의 머신별 `file:///` 경로는 공개 정답표의 저장소 식별자로 쓰지 않는다. 공개 수치에는 원격 저장소를 같은 고정 commit으로 새로 분석한 결과만 사용한다.

분석 후에는 별도의 독립 검토 기록을 만든다. 이 파일은 `analysis_id`와 사전 정답표 SHA-256에 결합하고, 사례별로 실제 확인한 후보·가설·Finding ID, 동일 흐름 판단 근거, 전체 Finding 인벤토리 검토 여부, Finding별 반증 또는 미검토 상태를 저장한다. 검토 기록을 수정해도 사전 정답표 바이트는 바꾸지 않는다. 기존 v1 oracle 안의 사후 매핑 필드는 과거 호환용으로만 읽으며, 새 v2 점수 산출에는 사용하지 않는다.

평가기는 저장된 분석 DB와 해시 검증된 아티팩트를 읽기 전용으로 읽는다. 기존 후보·가설 연결과 첫 누락 단계 진단을 재사용한다. 사례별 결과는 다음과 같다.

- `TP`: 독립 검토 기록에서 해당 source→sink 사례와 현재 Finding의 동일성을 확인했고, 현재 실행된 PoC·최종 TRUE·Technical Gate 및 보고서 증거가 유효하다. 하나의 사례에 여러 Finding이 연결돼도 TP는 1이다.
- `FN`: 해당 사례가 Python 검사 범위에 있고 관련 Python 파일·규칙, 후보/보안 표면, 심층 분석이 검증 완료됐으며 환경 검증이 가능하고 전체 Finding 인벤토리를 검토했는데 일치하는 TP가 없다.
- `HOLD`: 설치·Docker·외부 서비스·Agent 오류, PoC 미실행, 검증 실패, 정적 공백 또는 미완료 작업 때문에 TP/FN을 아직 정할 수 없다. 원인 코드를 함께 남긴다.
- `OUT_OF_SCOPE`: 사전 정답표가 표시한 필수 경로가 Python 제품 코드 밖에 있다. 비Python 제품 파일이 저장소에 존재한다는 사실만으로 별개의 Python 사례를 범위 밖이나 HOLD로 만들지 않는다.
- `REVIEW_REQUIRED`: 위치만 맞거나 근거가 모호해 동일한 흐름인지 독립 검토가 남았다. HOLD와 별도로 보여 준다.

Finding 단위의 `FP`는 독립 검토자가 사후 기록에 해당 Finding의 반증 근거를 기록했을 때만 센다. 정답표에 없는 Finding은 신규 실제 취약점일 수 있으므로 자동 FP가 아닌 `UNMATCHED_REVIEW_REQUIRED`다. 원본 Finding 수, 보수적으로 묶은 표시 그룹 수, oracle 사례 수, TP/FN 수를 별도로 보인다.

`TP / (TP + FN)`은 고정된 **평가 가능 Python 사례**에만 적용한다. 범위에 속하는 사례가 HOLD 또는 검토 중이면 완결 탐지율 대신 현재 확정 건수와 보류 건수를 출력한다. 정답표가 문서 예시 일부만 담았다면 결과명을 `문서화된 사례 탐지`로 제한하고, 저장소 전체 취약점 탐지율이라 부르지 않는다. 저장소가 명시한 전체 Python 사례라는 주장은 고정 커밋 기준 목록의 완전성을 독립 검토했을 때만 허용한다. 기술적 TP와 외부 제보 허가는 별개이며, Scope Gate의 `UNCERTAIN` 또는 정책 부재는 자동 제출 가능으로 해석하지 않는다.

## Python 미탐 개선 경로

먼저 기존 저장 분석과 작은 고정 커밋 저장소에서 `STATIC_CANDIDATE → DISCOVERY → HYPOTHESIS → VALIDATION → POC_ENVIRONMENT` 중 최초 공백을 사례별로 기록한다. DVPWA의 환경 HOLD나 비Python 템플릿은 Python FN으로 오인하지 않는다. 새 분석은 정답표 없이 실행하고 완료 후에만 비교한다.

확인된 Python 후보 누락은 해당 저장소 이름을 하드코딩하기보다 범용 source/sink 또는 AST 보안 표면 분류로 보완한다. 후보는 있지만 `EXCLUDE`가 문제면 불확실한 경우 `UNDECIDED` 보존과 근거 확인을 개선한다. 호출 경로 문맥이 부족하면 직접 callee의 필요한 부분만 유한한 크기로 추가한다. 이미 구현된 직접 callee 재시도 안내는 중복 구현하지 않고 실측한다. 모든 수정은 기존 안전한 배치·시간 제한·중복 방지·증거 인용을 유지한다. 환경 오류는 별도 HOLD로 두고 무분별한 자동 설치나 외부 서비스 실행으로 TRUE를 만들지 않는다.

전후 비교는 동일 커밋·설정·모델과 보관된 원본 결과로 하고, 수정 후 한 개의 별도 Python 저장소를 보류 평가에 사용한다. 정적 후보 포착, 적격 가설, 검증된 PoC/Finding을 각각 센다. 안전한 SQL 매개변수화, sanitizer, 서로 다른 SQL 흐름 등 음성·중복 회귀 사례도 검사한다. 관측된 FN이 없거나 환경 HOLD만 있으면 탐지율 개선을 주장하지 않고 그 사실을 남긴다.

## README와 문서

최신 main의 README를 기준으로 목적·Python 전용 범위·PowerShell 한 줄씩 실행하는 설치/설정/분석·`COMPLETE/PARTIAL/BLOCKED/HOLD` 해석·보고서 확인·안전한 제보 판단을 중심으로 재구성한다. 상세 migration, 프로필, 재개 예외, 비용 설명은 `docs/usage.md`, `docs/troubleshooting.md`, `docs/provider-setup.md`에 연결한다. `COMPLETE`는 계획된 범위 완료이지 취약점 부재나 모든 언어 검사 완료가 아니다. 신규 v2의 완료된 `STATIC_DONE` 정적 공백은 같은 ID의 resume로 재검사되지 않으며 새 분석 ID가 필요하다고 명시한다. 평가법과 보류/범위 밖 처리, 실제 시험의 한계는 별도 검증 문서에 기록한다.

## 실패 처리와 검증

잘못된 oracle/검토 기록 스키마, 중복 사례 ID, 위치·경로 오류, 대상 커밋·oracle 해시·분석 ID 불일치, 해시/DB 손상은 점수를 출력하지 않고 명확히 실패한다. 파이프라인의 `PARTIAL/BLOCKED/FAILED`를 평가기가 임의로 `COMPLETE`로 바꾸지 않는다. 기존 v1 oracle/저장 분석은 보존하고, 새 선택 필드가 없는 경우 기존 의미를 유지한다.

단위 테스트는 혼합 언어 저장소의 완전한 Python 범위, Python 정적 공백, 환경 HOLD, 독립 검토 전 후보, 같은 사례의 중복 Finding, 다른 흐름 오병합 방지, oracle 미완전성, 재개 후 중복 집계, read-only 실행을 포함한다. 회귀 테스트·타입/린트·README 명령 검증을 거쳐, 실제 고정 커밋 분석의 확인 가능한 수치만 검증 문서와 PR에 적는다. CI 또는 실제 재분석이 끝나지 않았다면 미완료로 보고한다.
