Bring the saved A-001 and A-002 analyses as far through the real pipeline as their pinned source, safe execution, and verified evidence allow. Reuse their current IDs and completed work. `COMPLETE`/100% must remain a statement about verified Python product-code scope, not a reward for exhausting retries; a vulnerability is `confirmed` only with its own valid evidence and PoC. If a real gap remains after bounded recovery, show it and retain `PARTIAL` or `BLOCKED`.

## Approaches and decision

1. **Chosen: additive proof and bounded replay.** Add a new, immutable A-001 evidence-plan version and a separately guarded A-002 late-candidate replay. Keep old checkpoints/artifacts, verify scope and child identity before any write, and rerun only newly justified work. This can improve both analyses without changing past results.
2. Relabel terminal `HOLD` or insufficient surfaces as `EXCLUDE`, `COMPLETE`, or 100%. This would claim coverage without route/child proof and contradict the existing completion certificate. Rejected.
3. Delete and restart both analyses. It might simplify state handling but would discard auditable work, repeat expensive calls, and violate the user's same-ID/reuse requirement. Rejected.

## A-001: source-bound v5 surface evidence

An explicit recovery entry point under the existing exclusive analysis lease pins the same workspace, commit, Python scope certificate, static bundle, AST manifest, candidate inventory, surface index, v1-v4 result refs, and child checkpoint identities. A deterministic `v5` plan targets the **current 36 insufficient surfaces**, records each prior reason and linked child state, and is stored once with a content hash. Repeated resume byte-compares that plan; it never edits the pinned v4 plan or reopens successful static/Discovery/Agent work. Missing or altered source/CAS data fails closed.

The call-path graph gains only general Python relationships provable from pinned source. In particular, a class method such as `do_GET`/`do_POST` can be treated as a standard-library HTTP entry only when inheritance from `http.server.BaseHTTPRequestHandler` is resolved to the imported symbol, not merely inferred from its spelling. Configuration-driven dispatch may add an edge only when a pinned configuration item, the parsing/lookup operation, and a uniquely resolved Python target are all connected; an arbitrary string, reflection, or external implementation stays an explicit dynamic-dispatch gap. Graph edges carry source locations, hashes, types, and the provenance of any standard-library contract. A route-to-sink chain cannot be fabricated by joining unrelated paths. Traversal is finite, deterministic, cycle-safe and bounded; limit exhaustion remains an explicit insufficient reason.

Each v5 surface receives bounded, redacted source/AST/configuration context in whole-item chunks, with no byte truncation. Reuse the existing surface-review Agent role and output validation; review only missing v5 parts and save responses and reasons atomically. A result may contribute `ENTRY`, `TRUST_BOUNDARY`, and `SENSITIVE_OPERATION` only when precise locations and graph edges validate against the pinned inputs and all roles belong to one connected path. Prior v1-v4 evidence stays addressable, and a new coverage artifact records both earlier and new refs. A model assertion or a `NO_HYPOTHESIS` without a complete graph is not negative proof.

For a source-proven non-request surface, save an explicit classification and its threat-model reason in the v5 artifact. It is **not** automatically `COVERED` or excluded; changing which indexed surfaces count toward completeness would require a separately reviewed certificate contract. If class initialization or a returning handler cannot satisfy the existing three-role rule, they remain insufficient in this recovery.

The 33 linked child `HOLD`s have a separate, explicit eligibility pass: compare the 25 claimed external prerequisites to the pinned project and prior evidence; inspect the 4 earlier generated-input `STOP`s for a demonstrably new testable input; and inspect the 4 exhausted inconclusive PoCs for genuinely new decisive evidence. Only a source/evidence-bound contradiction or new test path can authorize one bounded child replay, with its old output and decision preserved. Do not silently turn an Agent-declared prerequisite into an environment failure, invent dependencies, or reset retry counts. Unjustified or newly inconclusive children stay `HOLD`; failed child calls retain the existing failure semantics. No new Finding or `confirmed` verdict follows merely from graph coverage.

Finalization recomputes effective Python static gaps, v5 surface proof, pending work and child state. `COMPLETE`/100% requires zero effective static gaps, no pending/error child work, and every indexed surface `COVERED` under the current certificate. Otherwise a trustworthy terminal run remains `PARTIAL` with exact surface and child reasons; integrity or Agent failure remains `BLOCKED`/`FAILED`. CLI/dashboard/report must show completed review work separately from verified surface coverage so 33/33 reviewed is not misread as 33/33 proven.
